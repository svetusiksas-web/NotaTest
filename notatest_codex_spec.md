# Техническое задание для Codex
# Веб-сервис для создания и прохождения тестов по сольфеджио и музыкально-теоретическим дисциплинам

## 1. Цель проекта

Создать современный светлый веб-сервис для преподавателя сольфеджио, теории музыки, гармонии и музыкальной литературы.

Сервис должен позволять преподавателю:

- создавать тесты;
- добавлять вопросы вручную;
- массово вставлять сразу много вопросов;
- импортировать текст тестов из Word и Google Docs через копирование и вставку;
- добавлять к вопросам изображения;
- добавлять к вопросам аудио;
- использовать разные типы заданий;
- автоматически проверять ответы учащихся;
- рассчитывать баллы, процент и итоговую оценку;
- хранить результаты учащихся;
- видеть историю прохождений;
- в дальнейшем подключить базу данных;
- в дальнейшем подключить Telegram-бота для уведомлений о новых результатах.

Проект должен быть спроектирован так, чтобы сначала его можно было запустить как frontend-проект и хранить исходный код в GitHub, а затем без полной переделки подключить Supabase или другую базу данных.

---

# 2. Общая концепция

Это не игровой сервис наподобие Kahoot, а красивый профессиональный личный инструмент преподавателя.

Главная идея:

**Преподаватель создаёт тест → публикует → получает ссылку → ученик проходит тест → система автоматически проверяет → результат сохраняется → преподаватель видит результат в кабинете → позже получает уведомление в Telegram.**

---

# 3. Основные роли

## 3.1. Преподаватель

Преподаватель имеет доступ к административной панели.

Возможности:

- создавать тест;
- редактировать тест;
- удалять тест;
- дублировать тест;
- сохранять тест как черновик;
- публиковать тест;
- временно отключать доступ к тесту;
- копировать ссылку на тест;
- просматривать результаты;
- просматривать ответы конкретного ученика;
- фильтровать результаты;
- добавлять аудио;
- добавлять изображения;
- массово импортировать вопросы.

---

## 3.2. Ученик

Ученик не должен видеть административную часть.

Ученик открывает тест по ссылке.

Перед началом теста предусмотреть поля:

- Имя
- Фамилия
- Класс / группа — необязательно
- Дополнительное поле «Комментарий» — необязательно

В будущем должна быть возможность отключить или изменить эти поля.

# 4. Типы вопросов

Обязательно реализовать следующие типы заданий.

---

## 4.1. Один правильный ответ

Пример:

**Какой интервал содержит 5 ступеней?**

- Терция
- Кварта
- Квинта
- Секста

Правильный ответ: Квинта.

Интерфейс ученика — radio buttons.

---

## 4.2. Несколько правильных ответов

Пример:

**Какие интервалы относятся к чистым?**

- Прима
- Секунда
- Кварта
- Квинта
- Секста
- Октава

Преподаватель может отметить несколько правильных вариантов.

Интерфейс ученика — checkboxes.

Предусмотреть два режима проверки:

1. **Строгая проверка**
   - балл начисляется только если выбраны все правильные варианты;
   - ни один неправильный вариант не выбран.

2. **Частичная проверка**
   - начисляются частичные баллы за правильно выбранные варианты;
   - неправильные ответы могут уменьшать результат.

В первой версии можно реализовать строгую проверку, но архитектура должна позволять позже добавить частичную.

---

## 4.3. Короткий текстовый ответ

Пример:

**Как называется обращение трезвучия с терцией в басу?**

Ученик вводит:

`секстаккорд`

Преподаватель должен иметь возможность указать несколько допустимых вариантов:

- секстаккорд
- секстаккорд трезвучия
- 6

Настройки проверки:

- не учитывать регистр;
- автоматически удалять лишние пробелы;
- возможность указать несколько допустимых ответов;
- возможность включить или выключить строгую проверку.

В дальнейшем предусмотреть возможность ручной проверки отдельных текстовых ответов.

---

## 4.4. Сопоставление

Пример:

**Соотнесите интервал и количество ступеней**

| Левая часть | Правая часть |
|---|---|
| Прима | 1 |
| Секунда | 2 |
| Терция | 3 |
| Кварта | 4 |

Для ученика сделать удобный интерфейс.

Предпочтительный вариант:

- drag-and-drop;
- либо выпадающие списки;
- на мобильных устройствах обязательно должен работать без проблем.

Если drag-and-drop плохо работает на телефоне, использовать более надёжный интерфейс выбора соответствий.

---

## 4.5. Последовательность

Пример:

**Расположите ступени звукоряда по порядку**

- V
- I
- III
- II
- IV

Ученик должен перетаскивать элементы в правильный порядок.

Проверка производится по точному совпадению последовательности.

На мобильных устройствах предусмотреть кнопки:

- вверх;
- вниз;

или другой удобный способ изменения порядка.

# 5. Медиа в вопросах

Каждый вопрос должен поддерживать:

- текст;

- аудио;
- комбинацию текста + изображения;
- комбинацию текста + аудио;
- текст + изображение + аудио.

---

# 6. Изображения

Поддержать форматы:

- JPG
- JPEG
- PNG
- WEBP

Примеры использования:

- нотные примеры;
- фрагменты партитур;
- схемы аккордов;
- портреты композиторов;
- музыкальные инструменты;

После загрузки показывать preview.

Предусмотреть:

- удаление изображения;
- замену изображения;
- подпись к изображению — необязательно;
- alt-текст.

# 7. Аудио

Поддержать минимум:

- MP3
- WAV

В вопросе отображать аккуратный аудиоплеер.

Функции:

- Play
- Pause
- полоса прогресса
- громкость
- повторное воспроизведение

В дальнейшем предусмотреть настройки:

- разрешить неограниченное количество прослушиваний;
- ограничить количество прослушиваний;
- скрывать перемотку;
- автоматически запускать аудио.

По умолчанию:

- неограниченное количество прослушиваний;
- перемотка разрешена.

# 8. Массовая вставка вопросов

Это одна из ключевых функций.

Преподаватель НЕ должен быть вынужден вводить каждый вопрос вручную.

На странице создания теста должна быть отдельная кнопка:

**«Массовый импорт»**

После нажатия открывается большое текстовое поле.

Преподаватель может вставить сразу весь тест из:

- Word;
- Google Docs;
- обычного текстового файла;
- ChatGPT;
- другого документа.

---

# 9. Формат массовой вставки

Поддержать простой понятный формат.

Например:

```text
1. Какой интервал содержит 5 ступеней?
- Терция
- Кварта
* Квинта
- Секста

2. Какие интервалы относятся к чистым?
[*] Прима
[ ] Секунда
[*] Кварта
[*] Квинта
[ ] Секста
[*] Октава

3. Как называется первое обращение трезвучия?
ANSWER: секстаккорд | 6 | секстаккорд трезвучия
```

---

# 10. Правила распознавания массовой вставки

## Один правильный ответ

```text
1. Вопрос
- вариант 1
- вариант 2
* правильный вариант
- вариант 4
```

Символ `*` означает правильный ответ.

---

## Несколько правильных ответов

```text
2. Вопрос
[*] правильный вариант
[ ] неправильный вариант
[*] правильный вариант
```

---

## Короткий ответ

```text
3. Вопрос
ANSWER: ответ 1 | ответ 2 | ответ 3
```

Символ `|` разделяет допустимые ответы.

---

## Сопоставление

```text
4. MATCH: Соотнесите понятия

Прима => 1
Секунда => 2
Терция => 3
Кварта => 4
```

---

## Последовательность

```text
5. ORDER: Расположите ступени по порядку

I
II
III
IV
V
```

Порядок в исходном тексте считается правильным.

# 11. Умный парсер импорта

Создать функцию-парсер, которая:

1. принимает вставленный текст;
2. делит его на вопросы;
3. автоматически определяет тип вопроса;
4. распознаёт варианты ответа;
5. распознаёт правильные ответы;
6. создаёт структуру данных теста;
7. показывает предварительный просмотр.

После распознавания преподаватель должен увидеть:

**«Найдено 20 вопросов»**

и список карточек.

Для каждой карточки:

- тип;
- вопрос;
- варианты;
- правильный ответ;
- кнопка редактирования;
- кнопка удаления.

Обязательно сделать кнопку:

**«Импортировать вопросы»**

# 12. Импорт из Word и Google Docs

В первой версии достаточно корректного импорта через:

**Копировать → Вставить**

При вставке попытаться:

- убрать лишнее форматирование;
- сохранить абзацы;
- сохранить нумерацию;
- сохранить переносы строк;
- корректно обработать маркированные списки.

Не требовать прямой интеграции с Google Docs API на первом этапе.

Архитектуру сделать так, чтобы позже можно было добавить:

- загрузку DOCX;
- импорт Google Docs по ссылке;
- импорт CSV;
- импорт JSON.

# 14. Система баллов

Каждый вопрос имеет:

- количество баллов;
- правильный ответ;
- тип проверки.

По умолчанию:

`1 вопрос = 1 балл`

Но преподаватель может изменить количество баллов.

После прохождения вычислять:

- набранные баллы;
- максимальные баллы;
- процент;
- количество правильных;
- количество неправильных.

---

**«Не выставлять оценку, показывать только процент и баллы»**

# 37. Будущая логика Telegram

# 39. Безопасность Telegram

КРИТИЧЕСКИ ВАЖНО:

Telegram Bot Token нельзя:

- хранить в React;
- помещать в VITE_ переменную;
- публиковать в GitHub;
